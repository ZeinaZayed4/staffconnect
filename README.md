# StaffConnect

Internal staff portal for NovaTech Corporation. Employees can register, manage a profile with an avatar, reset a forgotten password by email, and publish, edit and delete company announcements.

Built with Django 4.2, SQLite (development), and Docker.

## Features

- Registration, login, POST-only logout, password reset by email.
- Profile with department, bio and avatar (validated: jpg/jpeg/png, max 2 MB).
- Announcements with pagination, detail page, and author-only edit/delete.
- Django Admin for HR (users, profiles, posts).
- Custom 404 page.

## Local setup (Python 3.11)

```bash
git clone https://github.com/ZeinaZayed4/staffconnect.git
cd staffconnect
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env             # then fill in the values
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

Open <http://127.0.0.1:8000>.

## Environment variables

All secrets are read from `.env`, which is never committed or built into the image.

| Variable | Description | Example |
| --- | --- | --- |
| `SECRET_KEY` | Django secret key | a long random string |
| `DEBUG` | Debug mode | `True` / `False` |
| `ALLOWED_HOSTS` | Comma-separated hosts | `localhost,127.0.0.1` |
| `EMAIL_BACKEND` | Email backend (console if unset) | `django.core.mail.backends.smtp.EmailBackend` |
| `EMAIL_HOST` | SMTP server | `smtp.gmail.com` |
| `EMAIL_PORT` | SMTP port | `587` |
| `EMAIL_USE_TLS` | Use TLS | `True` |
| `EMAIL_HOST_USER` | SMTP username | your address |
| `EMAIL_HOST_PASSWORD` | SMTP password (Gmail: app password) | |
| `DEFAULT_FROM_EMAIL` | Sender shown on emails | `StaffConnect <you@example.com>` |

Generate a secret key with:
`python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"`

With no email variables set, password reset emails are printed to the terminal, which is enough for local testing.

## Docker

Build:

```bash
docker build -t staffconnect:v1.0.0 .
```

Run (port 8000 must be free, the named volume keeps uploaded avatars across restarts):

```bash
docker run --rm --name staffconnect -p 8000:8000 \
  --env-file .env -v staffconnect_media:/app/media staffconnect:v1.0.0
```

Create an admin user inside the running container:

```bash
docker exec -it staffconnect python manage.py createsuperuser
```

Notes:

- Migrations run automatically on start (`entrypoint.sh`).
- `.env` is excluded from the image by `.dockerignore`; pass it with `--env-file`.
  Values in an env file must not be quoted.
- The container runs as a non-root user.
- SQLite lives inside the container, so data is lost when it is removed. For production, use PostgreSQL and a production server (gunicorn + static file serving).

## Design decisions

- The post slug is generated by the model (title + author username, with a numeric suffix on duplicates) and is read-only in the admin, so URLs never change when a title is edited.
- Profiles are created by a `post_save` signal, so every user (including
  superusers and admin-created ones) has one.
- Avatar validation lives on the model field, so it applies in forms and admin.
- Edit and delete are restricted to a post's author with `UserPassesTestMixin`, logout and delete are POST-only.

## Project structure

```text

users/      Profile model, auth views, forms, validators
posts/      Post model and class-based CRUD views
templates/  HTML templates
static/     CSS and default avatar
```
